# Mova UI-kit

Рабочий локальный MVP мессенджера Mova в тёмном стиле Liquid Glass.

Реализованы регистрация и вход, личные и групповые чаты, постоянное хранение сообщений, синхронизация через WebSocket и голосовые звонки через WebRTC.

## Запуск

Требуются Node.js 22.5 или новее и pnpm.

```bash
pnpm install
pnpm dev
```

Одна команда запускает frontend и локальный API. Приложение откроется на `http://127.0.0.1:5173`, API — на `http://127.0.0.1:8787`.

### Запуск двойным кликом на macOS

В папке `click` лежат готовые команды Finder:

- `Start.command` — запускает Mova в фоне и открывает сайт;
- `Test-Call.command` — запускает Mova и открывает две независимые вкладки для проверки звонка;
- `Test.command` — запускает тесты, production-сборку и интеграционную проверку;
- `Status.command` — показывает состояние web/API и последние строки лога;
- `Restart.command` и `Stop.command` — перезапускают и останавливают локальную Mova;
- `Deploy.command` — после подтверждения прогоняет проверки, создаёт коммит и отправляет его в GitHub.

Логи локального запуска сохраняются в `.mova-runtime/dev.log`, результаты последней проверки — в `.mova-runtime/last-test.log`.

Данные сохраняются локально в SQLite `.mova-data/db.sqlite`, а вложения — в `.mova-data/uploads`; оба пути не попадают в Git. При первом запуске существующий `.mova-data/db.json` автоматически импортируется, включая вложения и отметки о прочтении. Исходный JSON остаётся нетронутым как резервная копия.

SQLite работает в WAL-режиме с индексами по чатам, участникам и времени сообщений. Фотографии перед отправкой обрабатываются на устройстве пользователя: небольшие файлы сохраняются без изменений, крупные уменьшаются максимум до 4096 px и кодируются в WebP с качеством 93%. Перекодированный вариант используется только при заметном уменьшении размера. Сервер получает готовый бинарный файл, поэтому изображения не раздувают базу как base64 и не расходуют серверный CPU на обработку.

Для проверки общения между двумя пользователями откройте Mova в двух вкладках и зарегистрируйте разные аккаунты: сессии хранятся отдельно для каждой вкладки.

Во время первого голосового звонка браузер запросит доступ к микрофону. Для связи за пределами локальной сети потребуется HTTPS и production TURN-сервер.

## Desktop-приложение

Mova можно запускать как нативное окно Electron. В режиме разработки desktop-клиент сам запускает локальные web и API:

```bash
pnpm desktop:dev
```

Сборка установщиков:

```bash
pnpm desktop:build:mac
pnpm desktop:build:win
pnpm desktop:build:linux
```

Артефакты появляются в `release/`. При первом запуске production-сборка попросит указать публичный HTTPS-адрес Mova на Amvera; изменить его позднее можно через меню приложения. Desktop-клиент разрешает микрофон, уведомления и системный выбор окна для демонстрации экрана только для настроенного origin.

Проверка обновлений настроена через GitHub Releases. Для публичного распространения macOS-сборку нужно подписать сертификатом Developer ID и notarize, а Windows-сборку — подписать code-signing сертификатом.

## Публикация на Amvera

В репозитории уже находятся `Dockerfile` и `amvera.yaml`. При запуске в Amvera
приложение использует публичный порт `80`, база сохраняется в `/data/db.sqlite`,
а вложения — в `/data/uploads`. Старый `/data/db.json`, если он существует,
будет автоматически импортирован и сохранён как резервная копия.

1. Создайте в Amvera новое приложение и загрузите в него этот Git-репозиторий.
2. В разделе «Переменные» добавьте **секрет** `MOVA_SESSION_SECRET` со случайным
   длинным значением (не менее 32 символов).
3. Для стабильных звонков добавьте данные внешнего TURN-сервера как runtime-секреты:
   `MOVA_TURN_URLS` (несколько адресов разделяются запятыми, желательно UDP/TCP и
   TLS на 443), `MOVA_TURN_USERNAME` и `MOVA_TURN_CREDENTIAL`. Сам TURN нужно
   разместить у провайдера с публичными UDP-портами: HTTP/HTTPS-прокси Amvera
   медиатрафик TURN не заменяет. Вместо трёх переменных можно задать
   `MOVA_ICE_SERVERS` — JSON-массив в формате `RTCIceServer[]`.
4. Запустите сборку, затем приложение. После изменения переменных перезапустите контейнер.
5. В настройках сети добавьте бесплатный домен Amvera с типом подключения HTTPS
   и портом `80`.
6. Проверьте `https://<ваш-домен>/api/health` и `https://<ваш-домен>/api/ready`, затем откройте сам домен. Prometheus-метрики доступны по `/metrics`.

Для локальной проверки production-режима:

```bash
pnpm build
MOVA_SESSION_SECRET=local-production-check pnpm start
```

### Banner во время deployment

Maintenance-состояние хранится на persistent volume рядом с SQLite (`/data/maintenance.json` в Amvera). На backend задайте отдельный длинный секрет `MOVA_DEPLOY_HOOK_SECRET`. Deployment process должен использовать тот же секрет и публичный URL:

```bash
export MOVA_DEPLOY_URL="https://<ваш-домен>"
export MOVA_DEPLOY_HOOK_SECRET="<секрет из backend environment>"
MOVA_DEPLOYMENT_ID="deploy-$(date -u +%Y%m%dT%H%M%SZ)"

pnpm maintenance on "$MOVA_DEPLOYMENT_ID"
# Здесь выполняется фактический deploy новой версии.
pnpm maintenance wait-ready "$MOVA_DEPLOYMENT_ID" 900
```

`wait-ready` ждёт успешный `/api/ready` от нового `instanceId` и только после этого выключает banner. При ошибке или timeout команда завершается с кодом 1, а maintenance остаётся включённым. Для ручного снятия после проверки: `pnpm maintenance off "$MOVA_DEPLOYMENT_ID"`.

`scripts/deploy.sh` выполняет всю последовательность автоматически одной командой. По умолчанию он использует `https://hola-mova.ru` и получает secret из `MOVA_DEPLOY_HOOK_SECRET` или macOS Keychain (`service: mova-deploy-hook`). Secret в файлах проекта не хранится. Первый rollout поддержки maintenance выполняется обычным способом, потому что старая версия backend ещё не содержит hook endpoint.
