# Инструкции для нейросети

## Обязательная пересборка desktop-приложений

После завершения любых изменений продукта в `src/`, `server/`, `desktop/`, `public/`, `index.html`, `package.json` или конфигурации сборки не заканчивай задачу, пока не обновлены оба desktop-артефакта:

```bash
pnpm test
pnpm build
pnpm desktop:build:mac
pnpm desktop:build:win
```

Ожидаемые файлы:

- `release/Mova-<version>-arm64.dmg`
- `release/Mova Setup <version>.exe`

Проверь, что обе команды завершились успешно, файлы существуют и имеют ненулевой размер. На macOS дополнительно проверь DMG командой `hdiutil verify`.

Если изменения предназначены для нового опубликованного релиза или автообновления, сначала увеличь версию в `package.json` и синхронизируй её со ссылками на скачивание в `src/LandingPage.tsx`. Не заменяй уже опубликованный релиз файлом с той же версией.

Frontend Mova загружается desktop-оболочкой с сервера, но локальные `.exe` и `.dmg` всё равно должны быть пересобраны по просьбе владельца проекта. Если текущая операционная система технически не позволяет собрать один из форматов, не имитируй успех: собери доступный формат и явно сообщи, какой артефакт остался несобранным и почему.

Папка `release/` не должна добавляться в Git. Публиковать установщики в GitHub Releases можно только когда это входит в запрос пользователя или уже согласованный процесс выпуска.

## Работа с Amvera через MCP

Для управления хостингом Mova сначала используй настроенный Streamable HTTP MCP-сервер Amvera, а не браузерную панель:

- **Имя подключения в Codex:** `amvera-moscow`
- **MCP endpoint:** `https://openmcp.msk0.amvera.ru/mcp`
- **Production-проект:** `movamoskov` (`МоваМосков`)
- **Документация Amvera:** https://docs.amvera.ru/MCP/doc-mcp-ru.html
- **Документация Codex MCP:** https://developers.openai.com/codex/mcp/

Подключение хранится в глобальном `~/.codex/config.toml` и использует `bearer_token_env_var = "AMVERA_MCP_TOKEN"`. На рабочем Mac токен хранится в macOS Keychain с service `com.openai.codex.amvera-mcp`; после входа в систему переменную восстанавливают:

- `~/.codex/bin/load-amvera-mcp-token`
- `~/Library/LaunchAgents/com.openai.codex.amvera-mcp-env.plist`

Никогда не выводи значение `AMVERA_MCP_TOKEN`, не передавай его в логи/ответы и не записывай в репозиторий. Для безопасной проверки подключения используй `codex mcp list`: `amvera-moscow` должен иметь статус `enabled` и тип авторизации `Bearer token`. Если сервер только что добавлен или инструменты отсутствуют в уже открытой задаче, перезапусти Codex или начни новую задачу — текущая сессия не получает новый набор MCP-инструментов автоматически.

Через MCP доступны сведения о проекте, переменные окружения, домены, файлы, история коммитов, build/run/event logs, а также rebuild/restart. Начинай с read-only операций (`getProject`, `listEnvVars`, `getBuildLogs`, `getRunLogs`, `getEventLogs`). Значения секретных env-переменных не раскрывай. Удаление проекта, домена, переменной или файлов, остановка сборки и другие разрушительные операции выполняй только по явному запросу владельца и после проверки точной цели.

Для обычного выпуска кода сохраняется штатный порядок:

1. Пройди обязательные тесты и desktop-сборки из раздела выше.
2. Используй `./scripts/deploy.sh`: он включает maintenance, отправляет текущую ветку в GitHub и ждёт readiness нового instance.
3. MCP используй для наблюдения за статусом Amvera и журналами сборки/запуска. `rebuildProject` не заменяет отправку нового кода в GitHub.
4. После деплоя проверь `https://hola-mova.ru/api/ready`, выключенное maintenance-состояние, статус проекта `RUNNING` и отсутствие новых ошибок в run/event logs.

Если MCP недоступен, явно сообщи об этом и продолжи доступные проверки через `/api/ready`, `/metrics`, GitHub и панель Amvera. Не создавай новый MCP-токен, пока не проверены текущее подключение, Keychain и launch agent.

## Обязательная проверка production-стабильности через Grafana

При любых сообщениях о недоступности Mova, медленной работе, нестабильном соединении, ошибках HTTPS/TLS или возможном production-инциденте сначала проверь панель:

- **Mova — состояние сервиса:** https://chipperpoppy1894.grafana.net/d/mova-production/mova-e28094-sostojanie-servisa
- **Synthetic check:** `mova-availability`, запрос `https://hola-mova.ru/api/ready` из Stockholm каждые 5 минут.
- **Alert rules:** `Failed Checks [5m]` и `TLS Certificate` в Grafana Alerting.

Сопоставь время жалобы с доступностью, HTTP-кодом, общей задержкой и этапами `resolve`, `connect`, `tls`, `processing`, `transfer`. Если Grafana недоступна из-за отсутствия авторизации, явно сообщи об этом, но продолжи доступные проверки через `/api/ready`, `/metrics`, логи и тесты проекта. Не подключай платный тариф Grafana и не создавай токены доступа без отдельного разрешения владельца.

Grafana сейчас выполняет внешнюю проверку доступности и не содержит переписку, аудио или видео. Для проблем именно внутри звонка попроси пользователя скопировать анонимизированный «отчёт о звонке»: он содержит WebRTC-статистику, но исключает ID пользователей/чатов, IP/ICE-адреса, названия устройств и содержимое медиа.

Конфигурация панели и правил хранится в `ops/grafana-dashboard.json` и `ops/prometheus-alerts.yml`. После изменения запросов или метрик синхронизируй эти файлы с Grafana, чтобы настройку можно было восстановить.
